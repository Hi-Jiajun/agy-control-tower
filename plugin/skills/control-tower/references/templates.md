# 通用控制塔文本模板手册（Templates）

本手册提供跨工作区可即拿即用的 7 套标准模板；除通用占位符外不含任何特定硬件、硬编码配置路径或敏感字段。用户亦可在 Control Tower 看板「设置中心」对本手册做全局或单工作区在线覆盖，并可随时一键恢复内置默认。

---

## 1. 通用 `SESSION-REGISTRY.md` 初始骨架

> 适用于任意新建控制塔管理的工作区；若项目无独占物理/环境资源，可在看板关闭「独占资源单锁模式」或直接将锁状态标为 `无独占限制`。

```markdown
# 跨会话调度总账与资源租约登记表（SESSION-REGISTRY）

> **维护规则（总控独占写入）**：
> 1. 本文件是当前工作区所有长任务会话与调度状态的**唯一真相源**，由常驻主交流总控（`control-tower`）独占维护（并受 `PreToolUse` 钩子写入保护）。
> 2. **动态单资源锁（若本项目启用了独占资源锁）**：同一时刻最多 **1 个**专职会话持有独占资源；其余并行会话一律保持 **100% 纯离线**。
> 3. **交锁门禁**：换锁前必须核实上一持有者已清理临时环境并恢复安全基线态。
```

## 2. 任意新工作区首次开启总控的一键引导提示词

新建会话时工作区选中目标项目，模型推荐按当前总控设置选用新版满思考 **`Orchestrator (Neon Extra High)`**（或备选单模型 **`Gemini 4 Neon (XHigh)`**），粘贴如下提示词：

```text
从现在起，你作为当前工作区的「常驻主交流总控（Chief-of-Staff）」，与我保持长期单一主线沟通，并启用 control-tower 技能规范。

【请先完成首轮纯只读冷启动与就位】：
1. 启用已安装的 control-tower 原生插件技能，并查阅当前生效的路由规范与模板（若设置中心配置了全局或工作区覆盖文件，优先以覆盖版本为准）。
2. 盘点当前工作区基线规则与已有文档（检查根目录 AGENTS.md / GEMINI.md / .agents/ / README / 已有状态总账），确认两件事：
   a) 是否已有项目级控制塔规范或特殊红线（若有，以项目级规定为最高优先）；
   b) 本项目是否存在需要独占单锁管理的物理/测试/发布资源（若无，可建议在看板关闭独占资源锁模式）。
3. 查找是否已有 SESSION-REGISTRY.md；若尚未建立，向我确认落点路径（工作区 .agents/SESSION-REGISTRY.md、自定义相对路径或 PLUGIN_DATA 零侵入托管模式）并在建立后将你当前 conversationId 登记为第 1 任现役总控。
4. 严禁直接替我动手改业务源码、跑重构建或触碰独占资源；完成盘点后向我输出简洁的就位回执与当前工作区全景摘要，等我下达第一个需求。

【长期红线】：
- 默认遵循「隐藏面优先」派遣策略（优先通过原生 swarm / invoke_subagent / run_workflow 零左侧栏污染执行；原生 swarm 须显式传入 model 参数按舒适区配模），派单前按 askBeforeDispatch 设置询问推荐方案；
- 遵循生效代决策档位与 Antigravity 原生通知边界（单任务完成默认静默，阶段收口与需拍板事项才提醒）；
- 遵循 autoLearnMode 自动学习闭环：阶段收口、用户纠偏或换届前按原生 /learn 规范产出 learning_proposal.md 审批后再落盘（优先写当前工作区，绝不擅改规则与全局配置）；
- 总控换届默认阈值 5 次压缩且非强制，到达后由我选择换届或本会话忽略。
```

## 3. 总控换届交接卡模板（支持看板一键接班、`agentapi` 直派或手动粘贴）

前任总控在交接完成前保留 `SESSION-REGISTRY.md` 第 2 节自身 `conversationId`（可将状态标为 `HANDOVER`），并在交接卡首屏保留前任总控至少 8 位 `conversationId`；新总控首笔修改台账时同步把第 2 节 `当前现役总控会话` 更新为自身 `conversationId`，即可自动通过 `PreToolUse` 双证校验：

```text
请作为当前工作区「常驻主交流总控（第 <N> 任）」接班，加载并遵守已安装的 control-tower 原生插件技能及本工作区既有 AGENTS.md/项目规范。

【上任总控换届快照（<YYYY-MM-DD HH:MM>）】：
- 前任总控：<旧 conversationId>（已归档，原因：<压缩次数 / 里程碑收口 / 主动换届>）
- 工作区事实源：<列出 AGENTS.md / 状态总账 / SESSION-REGISTRY.md（含托管标记）精确路径>
- 当前设置与代决策档位：<独占锁开启或关闭 | 代决策档位 autonomous/balanced/strict | 换届阈值 | 生效覆盖文档路径>
- 当前独占资源锁：<无独占资源模式 / IDLE / 会话 conversationId（任务编号）>
- 活跃专职会话与 Swarm：<列出仍在推进的 conversationId 或活跃原生 swarm 标题与停靠点，没有填 无>
- 当前优先级与待办：<说清当前最高优先级、未闭环子项与阻塞点>
- 近期用户约定与偏好：<如有则列，没有填 无>

【首轮就位动作（轻量纯只读）】：
1. 启用 control-tower 技能并读取上述事实源与生效配置。
2. 在 SESSION-REGISTRY.md 更新现役总控槽位为本会话 conversationId 并追加第 2 节换届历史。
3. 严禁触碰独占资源，回复简洁就位确认后等我发话。
```

## 4. 两类标准派单开场提示词骨架（内嵌双向汇报锚点）

### 4.1 模板 A：直派 / 手动新建独立会话（含双向汇报协议）

```text
这是当前工作区的单任务专职攻关会话，请严格按以下唯一目标与约束推进：

【本轮目标编号与范围】：<编号> — <唯一目标>
【独占资源约束】：<【纯离线作业，严禁触碰独占资源/环境】 或 【持独占锁，允许按步骤验证】 或 【无独占资源限制】>
【必读基准与锚点】：
1. 工作区规范与总账：<AGENTS.md / 状态矩阵路径>
2. 本任务关键代码与证据路径：<精确文件或目录列表>

【跨会话双向汇报锚点（现役总控：<controllerId>）】：
1. 严禁直接修改 SESSION-REGISTRY.md（由总控与看板独占维护），亦严禁私自改写 AGENTS.md、.agents/rules/、.agents/skills/ 或全局规则技能文件。
2. 遇到需要拍板的架构/接口/范围分叉或连续两轮同一假设失败时，立刻调用：
   agentapi send-message "<controllerId>" "[CT_REPORT:DECISION] [<编号>] <分叉简述与备选方案>"
   然后暂停等待总控回复或用户指示，勿盲试。
3. 本轮任务验证通过收口时，向总控汇报交付成果、验证命令输出及可选经验候选（务必带上任务或路线图节点编号；无新教训则候选写「无」）：
   agentapi send-message "<controllerId>" "[CT_REPORT:DONE] [<编号>] <交付摘要、改动文件与验证结果> | 【可沉淀经验候选】：<1~3行根因/避坑约束或无>"

【执行与缓存纪律】：
1. 先查后改与批量只读：将已知独立的只读读取与检索尽量同轮批量合并，核对现有代码、配置与前序记录后再动笔，严禁长会话中途无故切换模型。
2. 精确读行再编辑：跨回合调用 edit_file 前必须先用 read_file 核对目标区域的最新文本与缩进，严禁凭印象盲填 Target；同一文件连续 2 次出现 target content not found 时，立即重读目标行段或改用 write_file 重写，严禁循环盲试。
3. 单变量可证伪推进：明确本轮成功判据，同一假设连续两轮失败立即止损汇报。
4. 收尾输出清晰的验证记录、变更文件列表与待同步要点。
```

### 4.2 模板 B：离线预跑转独占锁的「原会话续接授锁词」

当 B 会话已纯离线完成准备、A 会话安全交锁后，总控通过 `agentapi send-message` 直投或输出供用户发给原 B 会话：

```text
总控（<controllerId>）已核验前序会话 <A 的 ID> 完成收口并安全交还独占资源锁，现正式授予本会话全局唯一独占资源租约，请基于你本会话已准备好的离线方案与产物直接转入实测验证：

【当前资源前提与保护现场】：
1. 独占资源现处于安全基线态；<如保留了上一任务的临时运行态/内存态变更，写明保护路径与禁止覆盖/卸载边界；否则写 无历史残余现场>。
2. 请严格按分步判据逐项验证（先前置只读核对，再执行变更验证；同一假设连续两次未达预期立即停手还原并汇报）。
3. 遇分叉请示发送 [CT_REPORT:DECISION] [<编号>] 到总控 <controllerId>；全部验证结束（或止损回退）后，务必确认资源恢复安全待命态，并发送 [CT_REPORT:DONE] [<编号>] 汇报结果与交付清单给总控入账并释放租约。
```

### 4.3 模板 C：按需临时「域分总控（Domain Lead）」授权契约（通过原生 `swarm` 隐藏面派发）

仅在超大型并发项目需要临时分担某一子域推进时，由现役主总控作为 `swarm` 成员派发（零左侧栏污染、不裂脑）：

```text
你是当前工作区由现役主总控（<controllerId>）按需委派的临时「域分总控（Domain Lead）」，负责统筹子域：<子域名称与范围>。

【授权与单真源红线】：
1. 权限范围：仅负责本子域内的方案细化、子任务分工推进、接口联调与客观验收，允许在 Swarm 频道直接协调域内 worker。
2. 严禁越权：严禁推翻主总控已定总体架构方向，严禁直接修改 SESSION-REGISTRY.md 或私自授放全局独占资源锁。
3. 升级上报：遇到跨子域接口变更、需求范围调整或连续两轮假设失败，立即在 Swarm 消息板 @coordinator 暂停请示。
4. 收口回报：本子域全部目标验收通过后，向主总控提交不超过 10 行的结构化交付摘要（变更文件、验证命令与结论、遗留风险），随后进入待命态等待回收。
```

### 4.4 模板 D：跨波次接力契约卡片（`.agents/handoffs/<taskId>.md`）

上游分支完成验证收口后落盘的轻量只读契约，供下游分支直接承接（不读上游冗长对话记录，保护缓存）：

```markdown
# 接力契约：<taskId> — <分支标题>

- **里程碑 / 史诗**：`<M1> / <Epic>`
- **物理隔离与合流状态**：`workspace: share` -> 已合并 / 待 L4 合流
- **文件所有权范围（Ownership Map）**：`<改动目录与精确文件列表>`
- **对外接口与数据契约**：
  - `<导出的函数/CLI/API 签名、输入输出结构与不变量>`
- **客观验收命令与实测结果**：
  - 命令：`<exact test/build command>`
  - 结论：`<退出码 0 + 关键汇总输出>`
- **已知雷区与下游注意事项**：
  - `<边界条件、未覆盖项或禁止修改的共享约定>`
```

## 5. 日常与总控交互的高频快捷口令

| 场景 | 用户可发送的简短口令 | 总控预期动作 |
| --- | --- | --- |
| **提新需求要派遣** | `我想做 <某需求/修某问题>，帮我安排会话` | 默认按「隐藏面优先」通过 `ask_question` 推荐原生 `swarm` / `invoke_subagent` / `run_workflow`（仅白名单场景开顶层 `agentapi`），确认后拉起 |
| **处理后台信箱** | `处理一下后台收件箱` | 核查 `inbox.json` 中的 P0/P1/P2 待办项，集中批量更新台账与安排下一步 |
| **裸 ID 秒登入账** | `<直接发一串 conversationId>` | `PreInvocation` 自动提取头尾遥测，总控核查后同步更新 `SESSION-REGISTRY.md` |
| **查看或接手汇报** | `看看活跃会话和 swarm 进展` | 聚合查看四执行面状态（Swarm / Subagent / Workflow / 顶层会话），整理阶段汇报 |
| **收口转锁与换届** | `<旧 ID> 已做完，把锁转给 <新 ID>` 或 `准备总控换届` | 核查安全态后向新会话发送模板 B 授锁词，或引导选择立即换届（换届前顺带评估 `/learn` 经验沉淀并支持一键拉起新总控）/ 忽略提醒 |
| **沉淀复盘经验** | `/learn` 或 `汇总本阶段可沉淀经验` | 按原生 `/learn` 协议结合本阶段纠偏与专职经验候选生成 `learning_proposal.md` 提案，经用户审批后再落盘 |
